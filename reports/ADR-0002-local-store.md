# ADR-0002: Windows framed journal selected for the initial local foundation

Status: initial Windows foundation contract selected; full production store qualification remains phase-specific. Date: 2026-11-24. The adopted Windows storage/server graph passed the current advisory audit; see p00-security-disposition.md.

## Current decision and contract

Use the Rust framed file journal as the starting local persistence adapter. Keep MongoDB server-only and introduce no additional database. The tested contract is atomic draft+outbox batches, corruption rejection, bounded replay/quota, one cooperating writer across processes, explicit recovery after I/O uncertainty, and process-crash recovery. CRC is accidental-corruption detection, not encryption or authentication.

Windows compaction now closes data handles while retaining the stable sidecar writer fence, calls the exact windows-sys 0.61.2 `MoveFileExW` API with REPLACE_EXISTING and WRITE_THROUGH (without COPY_ALLOWED), reopens and flushes the resulting file before local success. The first attempt with open data handles correctly failed Windows integration tests with access denied; the close/replace/reopen sequence fixed it. Failure after replacement poisons the writer so no later append can ACK an obsolete handle. The regression test verifies explicit reopen and complete recovered state. The current 14 journal unit cases and six real process-termination compaction cases pass; native writer fencing remains tested across the handle gap.

Windows API source/license/MSRV were checked from the exact cached crate (MIT OR Apache-2.0; declared MSRV 1.71). Platform contract references: https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw and https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers . OS synchronous requests and process-crash tests do not prove physical device/power-loss behavior or protection from non-cooperating external file editors.

P00 starts with format v1 and no prior released application data. Unknown versions are rejected without rewriting, covered by a test. Future product schema migrations must be designed and tested before a schema-changing release, together with workspace directory scoping, secret references/encryption, backup/restore, physical storage qualification and final capacity budgets. These remain explicit product/release requirements; none is labelled verified by this foundation decision.

## Historical experiment observations

The following earlier notes preserve the evolution of the spike; current implementation/test counts and selection above supersede old adoption/blocking statements.

MongoDB is server-only. Offline desktop storage must not require mongod or silently introduce SQL. A Rust file journal/snapshot remains the candidate, not a confirmed product choice.

The isolated `spikes/p00` package implements a versioned framed journal. One frame contains both draft bytes and outbox bytes, monotonically increasing sequence, bounded payload, header and payload CRC32, and a commit marker. CRC is accidental-corruption detection, not cryptographic integrity or encryption. File::try_lock holds the exclusive lock for the writer lifetime. A returned local ACK follows write_all and sync_all; an I/O error poisons the writer until reopen. Incomplete final frames are truncated only after scanning complete validated records. Complete-frame corruption is rejected without rewriting the file.

Observed on Windows: 5 unit tests passed, including every truncated prefix of a second frame, a high-bit flip at every byte offset of a complete frame, exclusive writer, size rejection without damaging existing records, and a CRC reference vector. A child process writes and flushes draft+outbox, emits its post-sync ACK, is forcibly terminated by its parent, and the parent reopens and verifies both values. These tests exercise the local filesystem and Windows process semantics; they are not simulated repository mocks.

The continued spike adds a 32MiB file quota and 4,096-frame replay limit, checked before unbounded replay; it does not claim constant-memory replay. Full-state compaction writes and syncs a new frame, then atomically replaces the journal while a stable sidecar lock fences writers across file identity changes. Callers must supply complete draft+outbox state, not a mutation delta. Windows tests verify compaction/reopen/append, replacement writer fencing, failed compaction preserving prior data, oversized-file rejection without truncation and unknown-version rejection without guessing a migration. An actual OS write failure using a read-only handle verifies poisoned-writer recovery and preservation of the prior ACK. The process-crash smoke also tests that a second process cannot acquire the writer fence while the child holds it. The final unit run contains 10 passing tests; the separate native package has 3 additional history/virtualization tests.

Continuation evidence: a real parent/child process matrix now covers six compaction boundaries: created, partial write, full write, synced, replaced and ACKed. Every case checks the writer fence before termination, expected complete history after reopen, preserved draft+outbox and a subsequent append/reopen. A new append-path unit test injects StorageFull and WriteZero after every incomplete record prefix and checks no ACK/sequence advance, poisoned writer and recovery. The current suite has 11 journal tests and 3 native history/virtualization tests; the six process cases are additional integration observations. See `compaction-crash.md`, `compaction-crash-results.csv` and `durability-evidence.json`.

Remaining work before adoption: schema migrations, durable creation/directory metadata guarantees, physical disk-full and disk/device power-loss behavior, production workspace directory scoping and secret references. Deterministic injected errors and process termination are not physical disk/power evidence. The probe quota is not the final workspace capacity model. The spike stores opaque fixture bytes and has no production encryption claim. Do not plug it into a product and call storage durability accepted yet.

Evidence: `reports/raw/journal-unit.txt`, `reports/raw/journal-process-crash.txt`, `reports/p00-checks.json`. No production requirements are marked verified by these experiments.
