# Task card template

- Requirement ID(s):
- Phase / dependencies:
- Source behavior and linked screen/state:
- User-visible outcome:
- Shared data / private data / secret boundary:
- Domain + persistence/migration + API/permission changes:
- Dependency/SDK/API version checked and official source:
- Success / failure / cancel / offline / conflict / revoke behavior:
- Meaningful test / fixture / command:
- Windows visual/IME/DPI or benchmark evidence when relevant:
- Rollback / recovery:
- Actual status + remaining blockers:

A task is not verified until observable behavior and appropriate evidence exist. Avoid implementation-mirroring tests; check the contract and failure boundaries.
